These are the standing constraints from `docs/Plotlines_MVP_Redirection_Punchlist.md` §7, plus the acquisition, licensing, and privacy invariants accepted with the OSM acquisition review on 2026-09-03 (marked where they appear). Unlike an acceptance scenario, **none of them is checkable once.** They are invariants that hold across every implementation, review, and design decision, and most of them **do not fail loudly** — a violation ships as a quietly wrong behaviour, not a red test, unless someone wrote the test that catches it. That is why they live in a skill: so the check happens every time, not only when someone remembers.

## How to use this

This is a review gate, not a document to read once and forget. Before treating any Plotlines change as done — yours or one you are reviewing — identify which of the groups below the change touches and check it against those invariants. If the change is in the curation, reveal, consent, editing, or messaging path, at least one group almost certainly applies.

When a constraint here and a literal PRD/ARCH reading disagree, this skill wins for the invariant itself; when a constraint and a **measured spike** disagree, the measurement wins and both are a doc bug (see `plotlines-build`). Each entry names its FR / ARCH refs so you can read the origin.

## Story integrity and determinism

**No gamification.** No points, badges, achievements, unlockables, leaderboards, dice, or randomness anywhere. Every route, branch, and reveal is authored and deterministic — a Character who rides the same trip twice gets the same story. If a design introduces a random draw or a score-to-unlock, it has crossed a brand line, not added a feature. *(Brand Value 9, FR125)*

**The analysis never decides.** Co-location clusters *propose*; the Author *promotes*. Nothing enters a trip without an editorial act. A flow in which promotion is only reachable through an accepted proposal has inverted the dependency — direct promotion (layers → candidates → promote → roles) must always work without the analysis branch. *(FR102, FR110; ARCH P10)*

**Every stage after display is skippable.** An Author who knows the area drops a plot point and routes to it — no wizard, no forced pipeline. The pipeline (layers → notability → co-location → promotion → routing) exists to *remove* work, never to impose a sequence. If any stage becomes mandatory to reach the next, that is the violation. *(PRD §5; ARCH P10)*

## Reveal and safety

**Hazards are never hidden.** No Author, no setting, no role, no trip type can set a hazard or crux to revealed-on-arrival. Model-enforced, not UI-absence-enforced — the model rejects it on every path. A spoiled trip cannot be un-spoiled, but a hidden hazard is a safety failure, which is worse. *(FR115, C11)*

**Reveal is enforced at one gate.** Render, export, print, offline package, and plugin push all pass through `RevealResolver`. Hazards are exempt *inside* the resolver, so the exemption exists in exactly one place instead of being re-remembered at every surface. `tools/ci/reveal_gate_lint.sh` fails the build on Presentation-layer access to `Role.content` outside the resolver; §6A.2 adds byte-level assertions that unrevealed content is absent from every export format's output bytes (and from the string handed to the speech engine). The violating path is always a print preview, an export corner, or the TTS readout. On the Dart side the resolver is `client/lib/data/reveal_resolver.dart`, and H13 (#87, 2026-09-13) is its first Character-facing consumer: `data/character_journey.dart::buildPlotPoints` resolves every narrative role through it, and with no live arrival signal (ARCH §6.2's trigger engine is unbuilt) every on-arrival role is withheld — the same permanently-empty revealed set D59 chose for the anonymous reader, for the same reason. The Author-facing print previews (F1–F3) skip reveal **deliberately**, because the Author is reading their own trip; that is not a gap to close. *(ARCH P11, D39, D59; §6A)*

**A message is a template, not a sentence.** Every user-visible string resolves a fixed template against typed slots, with cause phrases drawn from a bounded table — never composed from call-site strings at runtime. This is a **safety** constraint as much as a scope one: a sentence assembled in Presentation is downstream of the export byte assertions and is therefore a path around the reveal gate that those assertions structurally cannot see. No template accepts `Role.content` or any authored text field. *(FR145; ARCH P11, D57, A30)*

## Consent and privacy

**Default nothing shared.** Every consent decision starts closed and requires an explicit Character action to open. **This survives cloning** — a clone never carries a grant or an arrival-visibility permission forward, because if it did, cloning becomes a consent-laundering path: last year's medical disclosure silently re-shared on this year's different trip. *(FR78, FR123, FR74)*

**Author notes never release.** Not withheld-then-released — **never**, in any state, by any path (export, print, share link, offline package, group relay, plugin `pushTrip`, TTS, trip archive). A bug that promotes a note to *withheld* is as bad as one that renders it, because *withheld* implies a future release and an Author note has none. Assert on output bytes, not code paths. *(FR135; ARCH P11)*

**Delete means gone.** No soft-delete column on `author_note`. Deletion propagates as an explicit tombstone, not as an absence — an absence gets union-merged back into existence by any device that never learned of the delete. An implementation that passes every other consent test and fails only "the notes come back after an offline device syncs" has this wrong. *(FR135a; ARCH §11.7, D51)*

**Never put a number on a person.** No cohesion score, compatibility rating, or ability index anywhere in the schema or the UI. Group-dynamics knowledge enters only as an Author's prose and as arrangement (grouping, pairing, sequencing). A Character's *own* stated preferences and their derived pace are a different thing and stay in scope. *(PRD D-N, non-goals §6.2)*

**Not a tracker.** Arrival events are discrete, sparse, tied to authored content, consented, and revocable. If a design ever needs continuous position sharing, it has crossed a non-goal. *(§6.2, FR123)*

**Arrivals are discrete by schema, not by discipline.** The arrivals endpoint accepts an anchor reference, never a bare coordinate, and **no position table exists anywhere in the schema** — deliberately. The gap between "post an event when a trigger fires" and "post position every 30 seconds" is one well-intentioned commit; the schema is what prevents it. *(ARCH §8.5, D43, A25)*

## Attribution, licensing, and data acquisition

*(The five below come from the OSM acquisition review and its licensing addendum, accepted 2026-09-03, rather than from §7 — but they are the same kind of rule: invariants that hold across every change and fail quietly. Read `docs/Plotlines_OSM_Acquisition_Review.md` for the full plan and `docs/Plotlines_Licensing_Position.md` for the ODbL reading behind them. Phases 0–3 closed on 2026-09-04 / 09-13 / 09-16 / 09-17 and #434 wired a stock install to the mirror, so the default path *is* the mirror now (ARCH D63) with public Overpass as the fallback when no clip is cached; since #453/#457 the basemap's tiles come from the mirror by default too, and ARCH D65 settled the basemap's acquisition as a TTL-refreshed per-region extract, never a planet archive. Phase 4 (hosted) and Phase 5 (the policy gate) are still open — the invariant is unchanged either way.)*

**Attribution is a build failure — and the gate covers every payload, not every *layer*.** Elevation (CC BY), the basemap (ODbL), the **routing graph** (ODbL, in its own right — #269 closed the hole where it was credited only by accident, inheriting the basemap's line), **Nominatim's display credit** (ODbL, in its own right — #296 closed it 2026-09-11 with a line beside each geocode search box, not only in About, because "reasonably practical" placement is near where the result lands), and every plugin layer's own terms are all owed, none substitutes for another, and all must propagate to exports and print. A layer with absent or unsatisfiable licence metadata **does not load** — refused at registration, not warned at render. The About surface enumerates loaded layers dynamically; it is never a hardcoded credit list. `web/about.py`'s gate has a dynamic half (loaded `LayerProvider`s) and a static half (`_STATIC_ATTRIBUTIONS`, asserted independently so an emptied constant is caught) — a new obligation joins one of those two, never a surface. Where the same licence covers distinguishable uses, each keeps its own entry and its own wording; a screen that repeats one credit verbatim three times is worse than one that says it once per use. One gate, every payload. **Software notices are a separate obligation with a separate list** (#267, addendum L5): the licence *texts* of the code the sidecar itself ships are generated into `THIRD_PARTY_LICENSES` at freeze time by `packaging/build_sidecar.sh`, and the freeze fails without them (or without PyInstaller's entry, whose GPL bootloader exception is the one the bundle exists to record in writing). `GET /about` carries them as `software_notices`, never folded into `attributions` — the two lists answer different questions, and merging them makes a missing data credit look like a missing licence text. There is no static fallback for notices on the client: "nothing to show yet" is the true state of an unfrozen build, unlike a data credit that is always owed. *(FR86, FR95, FR101, K10; ARCH §12.2, D45; addendum L5, L6)*

**Mirror the source; never hotlink a third party.** This is settled policy for basemap tiles and mechanical — `tiles/mirror.py` raises `HotlinkRefused`. The same policy governs OSM, and since Phase 3 (#272, ARCH D63) it is the shipped shape: bulk acquisition is a mirrored Geofabrik extract clipped per bbox on the Plotlines mirror, both `ensure_graph` and `OsmLayerProvider.fetch` read that one clip, and public Overpass is reached only as the fallback when no clip is cached — plus, once Phase 5.2 builds it, small, user-initiated, hard-capped live refresh. "Small and polite" is not a standard — the caps are four assertable numbers (bbox area **below** `max_query_area_size` so a query can never subdivide, concurrency 1, a per-day budget that fails closed with an honest message, **no automatic retry**: a user-initiated action that fails is re-initiated by the user or not at all). **Two of these are now mechanical, the rest are not.** #251 pulled forward the two Phase 5 tests that were testable without the transport swap — the default endpoint list cannot regrow, and no OSM request goes out under a default `User-Agent` — but the refusal itself is Phase 5 (#284), so the rest of the rule is held by review until it lands — and the fallback path is exactly where an endpoint would be added "just for now". A docstring full of excellent policy reasoning sitting above an endpoint list is precisely how that list grew the first time. Identify ourselves in every outbound request: a Plotlines `User-Agent` with a contact URL, never a library's default. **Coverage grows by the mirror fetching, never by the client reaching past it** (ARCH D67, epic #516): a miss becomes a fill on the mirror's own worker (`fetching` / `ready` / `no_upstream_coverage` / `failed:<reason>`, single-flight per area, client-key gated, never started by the anonymous reader), and the sidecar reads `fetching` as a retryable not-yet. A grey basemap outside the corridor is an honest bounded gap until then — "just point the tile upstream at Protomaps' hosted build for now" is the hotlink this rule refuses. *(§4, §10; addendum P4, P5, P6)*

**ODbL share-alike triggers on public use, not on handing over a file.** Making a derived database available over a network is Publicly Use — so hosted web, and arguably trip sharing, cloning, and the anonymous reading view **today**, implicate §4.4/§4.6, not just a future export. `docs/Plotlines_Licensing_Position.md` (adopted 2026-09-04, ARCH **D60**) records the verdict: OSM-derived data and authored content are a **Collective** Database rather than a Derivative one — **conditional on staying structurally separable.** That condition is the constraint, and it is the cheap structural move worth keeping intact: OSM-derived fields stay separably identifiable from Plotlines-authored fields (a per-feature source/provenance discriminator on the candidate record and on the promoted node), so an offer-the-database obligation is met by exporting the OSM layer rather than the whole trip store. A schema change that merges the two, or a promotion path that loses the discriminator, does not merely add work — it moves Plotlines to the Derivative reading. `AnchorProvenance` exists but under-reports on cluster promotion (#301). Retrofitting after Authors have data is the expensive version. The same reading is why `/clip` carries its own notice headers (#364): a clip is an *extraction*, so its output is a **Derivative** Database, not a Produced Work like the basemap archive — and Phase 4's hosted clip (#280) inherits that, same database over the same kind of channel. *(addendum L2, L3; Licensing Position §0; D60, #253)*

**A trip records which snapshot it was built from — and a pin that stops moving must be visible.** A trip pins its OSM build and does not shift under the Author mid-planning; the pin is **written into the payload** (`Provenance` in `trips/payload.py`), not just held in ops. Without it a trip built from a stale pin is indistinguishable from a fresh one, and an export carrying "contains OSM data, snapshot 2026-09-01" is a stronger §4.3 notice than a bare credit. #270 closed the producer gap 2026-09-12: `trips/provenance.py::build_provenance` is the **one** place a `Provenance` is built, wired into `/trips/split`, and its attribution list reuses `web.about.about_attributions()` so the graph's own credit travels with the trip rather than living only on About. `osm_source` is the machine-checkable pin, distinct from the free-text credit; since #277 (2026-09-16) it is **`geofabrik:<pin>`**, read off the clip's own directory rather than restated by hand, and `overpass:<fetch-date>` only on the fallback because Overpass has nothing versioned to pin to — same `<transport>:<id>` shape either way, and a placeholder or empty string there would be worse than the gap. #277 also made the pin travel: every export (FIT sidecar `.txt`, GPX `<desc>`, TCX `<Notes>`, GeoJSON properties, the itinerary) carries the ODbL notice **and** the snapshot pin from one `attribution_notice` source per language, so a new export format joins that source rather than composing its own line. The ops half exists too — `tiles/mirror_state.py` surfaces mirror age on `/health` and `docs/Plotlines_Release_Checklist.md` names a **person**, not a role, for the monthly bump of each data pin. Neither pin fails loudly when it stalls; an unchecked checklist item is a release shipping on data nobody re-confirmed, and since #375 the OSM re-pin has a flag (`--precut-wnc-corridor`) whose omission silently undoes a fix. #402 added the second quiet failure of the same shape: **deploying new clip code does not fix bytes already on disk** — the precut corridor extract has to be re-cut under the fixed code before a header-box fix is real in production, and nothing complains if it is not. The staleness monitor has failed the same quiet way from both sides since: the precut path never wrote `checked_at`, so every precut mirror read **stale** whatever its age (#471), and the Pi walkthrough published the basemap through `copy_basemap_standin.sh`, whose pre-#394 state shape made a nine-day-old extract read **628.5 days** (#468). A monitor that is wrong in either direction teaches the reader to ignore it. The basemap pin is now a cron-refreshed path with its own 30-day TTL (D65) — distinct from Geofabrik's 45, never shared — and the Release Checklist's basemap item is *confirm the refresh cron is healthy*, not a hand bump. *(addendum L7, Q2; #270, #277, #375, #402, #457, #468, #471)*

**Say truthfully what leaves the device.** A user-facing accuracy claim about data egress is a constraint, not copy — **when the behaviour changes, the sentence changes in the same commit.** The privacy statement (`client/lib/domain/privacy_statement.dart`, mirrored in `web/about.py`, pinned by tests on both sides, reachable from every surface) said planning sent nothing anywhere while drawing a bbox went to a volunteer-run third party and `/geocode` sent the Author's typed place name to Nominatim; #252 corrected it, and its `planning_requests` point now names both recipients and their jurisdictions. That made it a live pin, and it moved as required: #274 named the Plotlines-operated mirror as the first recipient, Overpass as the fallback, and Nominatim for geocoding — in the order the shipped app actually tries them — inside the same PR (#426) that wired the extent-triggered clip download, before #434 made a stock install reach it. It has moved twice more since, both in the PR that changed the behaviour: #514 added that viewing the map outside the home region asks the mirror for the tiles on screen, and #148 (PR #528) added OpenTopography — together with the fact that **its request carries the API key, which identifies whoever registered it**. That second half is the part easiest to miss: the statement closes on "none of these requests carries your account, your name, or any other identity", and a new recipient that carries a *credential* makes that sentence false by omission, so it now reads "apart from that key". The next recipient change (Phase 4's hosted clip, D67's fill worker, a different mirror URL) moves the sentence in its own commit too, and asks the same question: does this request carry anything that identifies someone? Defaulting a flag that points at an *already-named* recipient is not a recipient change, but it can be a timing one: #367's default `--mirror-state-url` is a read of the mirror *before any extent is declared* — the posture #274 refuses for `/clip` — and was accepted only once it was cached for an hour rather than repeated on every 2 s poll. A new pre-extent request needs that argument made explicitly, not inherited. *(D41, D57)* Neither may the sentence be quietly narrowed as a way to make it true again. *(FR138, K10; addendum P1; #252)*

## Navigation scope

**Not a nav device.** GPS triggers authored content and advances a glanceable cue sheet. No turn-by-turn, no wrong-turn recalculation, no follow-the-line guidance. GPS-triggered narration and cue-sheet advance are in scope; live guidance is not. *(§6.2)*

## Data-model discipline

**Candidates are not canon.** Candidates live in a regenerable, bbox-scoped cache keyed by layer set *and* ruleset version. A promoted anchor **copies** the geometry, name, tags, and provenance it needs — it never holds a reference into the cache. Deleting the cache must cost a re-extraction and never authored work. **And there is one promotion path, not one per surface**: `domain/promote.dart::promoteAnchor` does the copy, the role pre-fill and the duplicate check, and a surface that promotes by writing something else has produced a pre-v2 object — the Layers tab's map tap, the highest-traffic path, wrote a `Day.nodes` entry with no roles, provenance, area or duplicate check until #477. On the map, promotion *moves* a mark from cache to canon: the source candidate's pin and ring are retired by source id and an `AnchorMarker` / area ring stands in their place (#410, #484), so a promoted place is never drawn twice and never offers a second promotion. *(ARCH §4.2, D36, D37; #403, #410, #477, #484)*

**Display formats never reach stored data.** Date, time, and unit preferences are render-time transforms only. ISO 8601 is the sole stored, exported, filename, and content-digest form. A display format in a payload makes the content digest depend on who was looking at it. **The render-time half is mechanical on the client since #399**: `client/test/display_format_gate_test.dart` fails the suite on any `DateFormat(` in `lib/` outside the ISO stored form and the date-range picker's two named chrome patterns, so a surface that shows a date, clock, or distance asks `DisplayFormat` (K5, FR79) and never `intl` directly. Four surfaces ignored the date/clock preference for weeks because nothing stopped a `DateFormat('MMM d')` from landing — the gate is what stops the next one. *(ARCH D49; FR79, K5; #399)*

**Two authoring extents, never conflated.** The **shipped home region** (Buncombe County rectangle — a compile-time constant, no override, no prompt, no download) and the **trip bbox** (drawn by the Author; bounds candidates, clusters, tiles, elevation). The **offline corridor buffer** is Character-side and never appears in the authoring flow. Conflating the last two has Characters downloading a county to ride a corridor. Every extent is justified by a trip, except the one that costs nothing. **Editing the trip bbox offline is decided, not improvised** (ARCH D62, #278/#432): a *shrink* is served as a `provisional` graph truncated from the held wider one — `ready: true` with a distinct `provisional: true` flag and an honest sentence, never a plain ready — while a nudge or grow reports `failed:<reason>` because nothing held covers the new area; Q1's client-side re-clip fallback is rejected on measurement and must not be reintroduced as "just clip locally". FR120's no-lost-anchor guarantee holds identically against a provisional result. *(ARCH D41, supersedes D32; D62)*

**A list is a seed set; state the rule beside it.** An enumerated list in a requirement is a seed set unless it explicitly says otherwise, and the rule that generated the list must be written down next to it — if the rule is not stated, the list gets implemented *as* the rule. Applies to notability rules, role affinity, Set detection, routability constraints, the **discipline registry** (#315 — the rule: a discipline is a travel-mode *category* plus a `WeightProfile` plus a `grades_difficulty` capability flag; `multimodal/disciplines.py` and the schema's `$defs/discipline` are one mirror, pinned by `test_disciplines.py`), the **station-activity registry** (O4), the **trip's mode set** (#319, ARCH D64 — the rule: one stored `Trip.modes`, set at initiation, grown by the Author or by a passage arriving in an undeclared mode, never shrunk automatically; the passage picker is a filtered choice from it with no default), and anything added later that reads like a lookup table. With plugins this turns a limitation into a *silent* failure: an unlisted type produces no proposals, no error, no log. *(§0; PRD D-L)*

**Affinity is declared by the layer, never inferred by the core.** A core-side type→role lookup table is the §0 failure mode in its highest-consequence location: plugin layers silently produce zero proposals because no entry exists for their types. Each layer declares its own role affinity in the contract; a cluster proposes the union of the affinities present, and the Author overrides the rest at promotion. *(ARCH D47; FR100, FR105)*

## Editing model

**Orphaned authored work prompts; invalidated derived work goes stale.** Two mechanisms, never merged. A confirmation prompt belongs only where an action *destroys* something an Author made — removing a passage that carries anchors and content, cutting days that hold content. It never belongs where an action merely *recomputes* a route. Two September instances, both the shape to copy: orphan-node cleanup that drops a routing-constraint node marks the segment **stale** rather than re-solving or prompting (#389), and removing an anchor, node, or segment **detaches** the Hazard and Permit references that pointed at it rather than leaving them dangling (#388) — a dangling reference is neither orphaned authored work nor stale derived work, it is a third state the model must not have. *(FR139, FR140; ARCH §7.10, D-O; #388, #389)*

**Nothing recomputes on its own.** An edit marks derived work stale; re-solving is an explicit call, and re-solve-all clears every stale marker in one unconfirmed action. Eager recompute is the Riverpod layer's *default* unless someone opts out, so this needs active watching, not assuming. What counts as an invalidating edit is decided per field, not inferred: a change of a passage's parent travel mode marks the route stale, a change of discipline within that parent does **not** (#319, D64 — the owner's call, and flagged in PR #443 as the one weight-affecting edit that stays fresh; do not "fix" it without reopening that decision). *(ARCH D52, A28; #319)*

**Two things sit deliberately outside the shared error surface** — compose-mode distance deviation and the stale list. Routing either through the shared error/M13 path teaches the Author that ordinary editing produces errors. A 94-mile compose day is an editing outcome with drop/defer/split/widen/accept affordances, not a conflict dialog; a stale export attempt opens the stale list, not an error. The converse holds too: a *partial* layer extraction **is** an M13 state — the fifth v2.0 one, layers-partially-served (#400), which names each missing layer and its reason under itemised detail lines and never renders as an empty area. The surface is for things that went wrong; a subset that arrived quietly, looking complete, is the confidently-wrong state from the advisory rule below. **What reaches the surface is a finished sentence, never an exception.** Every thrown path converges on the same M13 treatment as its non-throwing sibling (#418 retired the Layers tab's `_ErrorBanner`, which rendered `e.toString()`): use an exception's `.message`, never its `toString()`, and pass anything that isn't a sentence the sidecar wrote through `looksLikeRawDiagnostic` — a repr, a traceback or a `host:port` becomes a fixed phrase. A client-side timeout is converted to the same typed exception an ordinary sidecar error raises (#496), so no `TimeoutException` or `SocketException` reaches a catch block that displays `.message`. *(FR118, FR140a, FR145; ARCH D53; #400, #418, #496)*

## Request threads

**No shared-pool thread waits on the network, and a transport failure is never latched.** ARCH §8.6 / D66 / A30. No library timeout covers DNS, a lock held across a socket makes every waiter as unbounded as its holder, and a client timeout does not free the server thread — so every outbound call runs on a dedicated pool behind a caller-side deadline and degrades to an honest answer; no lock is held across a socket and every lock wait is bounded (`Lock.acquire(timeout=)`); and every client call to the sidecar carries its own deadline. This fails **quietly** twice over: a stuck call looks like a slow endpoint until enough polls pile up to starve `/health`, and every one of #488 / #490–#496 sat under a docstring explaining why *that* call was safe. #497 made most of it mechanical — `service/tests/test_request_thread_contract.py` wedges four endpoints at once and asserts the rest answer, and AST-walks every handler for a direct outbound call — but the gate cannot see a *library helper* a handler calls that dials out underneath it (#504 was exactly that: #490 patched `/candidates`' caller, not the shared extraction `/clusters/analyze` also used). The latching half is held by review: a `CandidateFetchUnavailable`, a timeout or a DNS blip is a fact about this *request*, never about the layer or the region — record it in the per-request error map, negative-cache it briefly if repeating it would cost the upstream (60 s, #491), and let the next request make a real attempt. Latching it turned one blip into "curation is broken until you restart the app." A failure that *is* a fact about the thing — a missing licence at registration — still latches. **A hot read-through also bounds its queue** (#514, `_upstream_tile`): the map requests tiles by the dozen, so a pool plus a deadline is not enough on its own — at most 8 callers wait before a tile answers 503 at once, which caps what a wedged mirror can hold at 8 shared threads for 5 s. And the status code carries the distinction: a transport failure is a retryable **503**, never the **404** that tells the client "there is no tile here". *(ARCH §8.6, D66, A30; #488, #491, #497, #504, #514)*

## Interface

**Teaching is first-run and dismissible; explanatory copy is never permanent furniture.** A caption that states a rule usually exists because the interface failed to demonstrate that rule. Dismissing a tip hides it for that trip only; a new trip shows it again; every dismissed tip stays reachable from inline help on its own surface; dismissing all of them leaves every control operable. Live status text ("routing available in about 3 minutes") is not teaching — not dismissible, not in the enumeration. **Registering a tip in the K12a registry is not shipping it.** Four of K12a's original tips (#347, #353) sat registered but never mounted, with no help affordance, reading as present in every test and every registry dump; they closed 2026-09-11/12 by being mounted, with no registry change at all. A teaching moment is done when it is *mounted on its surface* and reachable from that surface's inline help — and a test that only inspects the registry cannot tell you that. *(FR142(e); K12a; #347, #353)*

**A capability with no path back to what it made is not usable.** Every new object type ships with its reachability path named — the surface it is found on, and how to reach it. This is a rule you check forever, not a feature you build once: the unattached-anchor hole is what happens when it is skipped. Run the enumeration whenever a new object type is added. The map is part of the enumeration: an Anchor reached cards, dropdowns and lookups on every tab and had **no mark on any map** until #410, and an area anchor's hand-drawn boundary reached none until #484 — "findable in a list" did not make it present on the surface an Author looks at most. *(PRD FR142(b), K12; #410, #484)*

**WCAG 2.2 AA is the floor, not the target.** Field surfaces exceed it deliberately for outdoor legibility and gloved operation. At MVP it is a design-review checklist; the formal WCAG 2.2 AA audit is a scheduled gate (Leg 6.75) before any expansion beyond the Author desktop, with named owners for keyboard navigation, screen-reader semantics, and focus management. *(PRD FR142, FR142a)*

## Advisory vs constraint

**Advisories warn; constraints exclude.** Gauge bands (FR14), vehicle-access signals (FR29a), and difficulty grades are **advisory** — they surface and warn, they never reroute or exclude. Mode-legal routability (FR128) is a **constraint** — it excludes. Keep the two categories apart: an advisory promoted to a constraint takes a judgment away from the Author; a constraint demoted to an advisory ships an unridable route. An unflagged advisory reads as "no contrary signal found," never as "confirmed passable." *(FR14, FR29a, FR128; ARCH §7.4)*

**Thin coverage produces confident understatement, not silence — so every reading states its source and coverage.** This is the measured half of the rule above, and it is why the honesty payload is not optional decoration. SPIKE-C: a leg grade is worst-of its ways, a worst-of over a sample is biased low **by construction**, and at real North American tagging rates 16–32% of aggregated land grades would be wrong and *all of them too easy* — so nordic `piste:difficulty` aggregates and `sac_scale` / `trail_visibility` / `mtb:scale*` never do, with the Author's declaration the **primary** source for land difficulty rather than the fallback. SPIKE-E found the same shape in vehicle access: a 35%-surveyed gravel approach reporting "no signal exceeds 2WD" is the confidently-wrong state, and it lands at 18.8% against a pre-declared 10% ceiling. The sparse state must be structurally incapable of rendering as the complete one. The same holds when there is no data at all: an elevation source that never resolved reports elevation **absent**, not a flat 0.0 profile (#466) — a fabricated flat line reads as a measured easy day. **FR88 now has two cases (#473, ARCH D68)**: a *gap* in a raster that opened is interpolated from its real neighbours (a nodata pixel filled to 0.0 used to invent a plunge to sea level and count it as ascent), and an *absence* is absent everywhere — no sampler, a `{}` profile, no attribute on the graph. **And absence is stated per area, not hidden behind a process-wide flag** (#148, D69): with a key configured the sidecar's `elevation` reads ready, while a given area the daily allowance or the network left without data carries its own finished sentence under `elevation.regions` — a surface that gates climb on the process-wide flag alone would show that area a climb of 0 m. Read the region's own status. *(FR14b, FR29a, FR88, B8, B9, C13a; ARCH §7.4, §7.5, D68, D69; #466, #473, #148)*

## The two §0 tests these rest on

Several constraints above are instances of the two failure modes §0 identifies. Re-run both after any significant editing pass on the docs or the model:

- **Find-and-replace test.** If you could globally swap *Author → Planner*, *Character → Participant*, *plot point → waypoint*, *Passage → Segment* and nothing breaks, the story frame has degraded back to vocabulary and the recomposition is undone. Story is structure — it determines what objects exist and how the app behaves.
- **Seed-set test.** For every enumerated list touched: is the rule behind it stated alongside it? If not, the list will be implemented as the rule — and with plugins that becomes a silent failure, not a visible limit. *(FR98, FR105, FR111, FR128 were rewritten on this basis.)*
